Dataset Sintético bajo
ISO/IEC 25012 e ISO/IEC 27701

30 registros de pacientes de una clínica médica ficticia, diseñados desde cero para cumplir con los requisitos de calidad de datos (ISO 25012) y gestión de privacidad (ISO 27701).

01 — Descripción General

Resumen del Dataset

Contexto, dominio y normativas aplicadas al diseño del dataset sintético.

🏥
CONTEXTO DEL DATASET
Registros Clínicos — Clínica San Rafael (Ficticia)

Dominio: Salud / Registros médicos de pacientes.

Justificación del dominio: El sector salud es uno de los más exigentes en términos de calidad de datos (errores pueden comprometer tratamientos) y privacidad (los datos médicos son datos sensibles/especiales). Esto hace que sea el escenario ideal para demostrar la aplicación rigurosa de ambas normativas.

Ficha Técnica

  • Total de registros: 30 pacientes
  • Total de columnas: 24 variables
  • Formato: CSV (dataset_sintetico.csv)
  • Valores nulos: 0 (completitud del 100%)
  • Normativa 1: ISO/IEC 25012:2008 — Modelo de Calidad de Datos
  • Normativa 2: ISO/IEC 27701:2019 — Gestión de Privacidad de la Información

03 — Normativa 1

Cumplimiento ISO/IEC 25012

Cómo la estructura del dataset satisface las características de calidad de datos definidas en la norma.

📐
ISO/IEC 25012:2008
Modelo de Calidad de Datos — 10 Características Aplicadas

La ISO/IEC 25012 define 15 características de calidad de datos. A continuación se demuestra cómo 10 de ellas se implementan directamente en el diseño del dataset:

✓
1. Exactitud (Accuracy)
Los diagnósticos incluyen tanto texto descriptivo como código ICD-10 estandarizado internacional, garantizando que cada diagnóstico sea exacto y verificable contra una referencia global.
DiagnosisCode_ICD10 → I10, E11, J45...
✓
2. Completitud (Completeness)
0 valores nulos en los 30 registros. Todas las variables obligatorias tienen datos. DischargeDate solo está vacío cuando el paciente sigue en tratamiento (ausencia justificada, no dato faltante).
DataQualityScore promedio → 0.956
✓
3. Consistencia (Consistency)
La edad (Age) es coherente con la fecha de nacimiento (DateOfBirth). Las fechas de alta son posteriores a las de admisión. Los estados de tratamiento son coherentes con las fechas.
Age = 2026 - Year(DateOfBirth)
✓
4. Credibilidad (Credibility)
Cada registro incluye RecordSource (sistema de origen) y AttendingPhysicianID (médico responsable), permitiendo verificar la procedencia y autoridad de cada dato clínico.
RecordSource → Sistema HIS v4.2
✓
5. Actualidad (Currentness)
El campo LastUpdated registra cuándo fue la última modificación de cada registro. Los pacientes activos tienen fechas recientes (septiembre 2026), los dados de alta tienen fechas anteriores.
LastUpdated → 2026-09-13
✓
6. Accesibilidad (Accessibility)
El dataset está en formato CSV estándar, universalmente legible por cualquier herramienta (Excel, Python, R, SQL). Los IDs estructurados (PAC-XXXX, MED-XXX) facilitan búsquedas y filtrados.
Formato: CSV UTF-8
✓
7. Conformidad (Compliance)
Las fechas siguen el estándar ISO 8601 (YYYY-MM-DD). Los diagnósticos usan el estándar ICD-10 de la OMS. Los IDs siguen un patrón consistente con prefijo + número secuencial.
Fechas: ISO 8601 · Diagnósticos: ICD-10
✓
8. Confidencialidad (Confidentiality)
Los emails están enmascarados (m****a@correo.com) y los teléfonos están hasheados criptográficamente (irreversibles). Los médicos se identifican por ID, no por nombre.
Email → m****a@ · Phone → a3f1b2c8...
✓
9. Trazabilidad (Traceability)
Cada registro tiene RecordSource (origen del dato), LastUpdated (última modificación) y DataQualityScore (puntaje de calidad), permitiendo rastrear la historia completa del dato.
RecordSource + LastUpdated + QualityScore
✓
10. Comprensibilidad (Understandability)
Los nombres de columnas son descriptivos en inglés estándar (PrimaryDiagnosis, TreatmentStatus). Cada diagnóstico incluye texto legible junto al código técnico ICD-10 para ser comprensible por diferentes perfiles.
PrimaryDiagnosis + DiagnosisCode_ICD10
04 — Normativa 2

Cumplimiento ISO/IEC 27701

Cómo el dataset implementa los controles de gestión de privacidad exigidos por la norma.

🔒
ISO/IEC 27701:2019
Gestión de Privacidad — 8 Controles Implementados

La ISO/IEC 27701 define controles para gestionar datos personales (PII). A continuación se demuestra cómo 8 controles clave se reflejan en la estructura del dataset:

✓
1. Consentimiento Granular
Se registran 3 niveles de consentimiento separados: procesamiento de datos médicos, uso para investigación, y comunicaciones de marketing. Cada paciente puede aceptar o rechazar cada uno independientemente.
ConsentDataProcessing · ConsentResearch · ConsentMarketing
✓
2. Minimización de Datos
Solo se recopilan los datos estrictamente necesarios para el tratamiento médico. No se almacena dirección, número de seguridad social, religión, ni otros datos innecesarios para el propósito declarado.
24 columnas esenciales — sin datos excesivos
✓
3. Limitación de Propósito
El campo DataPurpose declara explícitamente el propósito del procesamiento ("Tratamiento Médico"). Los datos no pueden usarse para fines distintos al declarado sin nuevo consentimiento.
DataPurpose → "Tratamiento Médico"
✓
4. Base Legal Documentada
Cada registro tiene un LegalBasis que justifica el procesamiento: "Consentimiento Explícito" para la mayoría, e "Interés Vital" para pacientes de emergencia que no pudieron consentir previamente.
LegalBasis → Consentimiento Explícito / Interés Vital
✓
5. Pseudonimización de PII
Los datos de contacto están pseudonimizados: emails con enmascaramiento parcial (m****a@correo.com) y teléfonos con hash criptográfico unidireccional (a3f1b2c8d9e0). Se reduce el riesgo de reidentificación.
Email: enmascarado · Phone: hash SHA-256
✓
6. Limitación de Retención
El campo DataRetentionYears define cuánto tiempo se conservarán los datos: 10 años para pacientes activos (requisito legal médico) y 5 años para pacientes dados de alta. Después, los datos deben eliminarse.
DataRetentionYears → 10 (activo) / 5 (alta)
✓
7. Identificación del Controlador
El dataset identifica quién es el responsable de cada tratamiento mediante AttendingPhysicianID, y el sistema de origen (RecordSource). Esto permite ejercer derechos del titular directamente con el responsable.
AttendingPhysicianID → MED-042, MED-018...
✓
8. Datos Sensibles de Salud
Los datos médicos son categoría especial de PII (datos sensibles). El dataset garantiza su protección con: pseudonimización de contactos, consentimiento explícito obligatorio, y propósito restringido exclusivamente a tratamiento médico.
Categoría: Datos de Salud (Art. 9 GDPR compatible)
